# AI 分析（计划，未实现）

日期：2026-11-03。状态：计划草案，等用户确认后再动手。

用户的问题：能不能接入 AI 分析——MarketLens 自己有 AI 接口，或者 Cirra 开着时交给她的 AI；之前回测效果差，是不是因为没结合时事、K线和各种指标、计划不合理；用 AI 多角度分析会不会更好。

## 1. 之前的回测测了什么、为什么没找到优势

测过的（docs/BACKTEST.md 第 12–16 节，黄金 GC=F 2001–2026 日线、比特币 2018–2026、eToro GOLD 2023–2026，计入成本，有样本内外拆分和置信区间）：

| 测了什么 | 用到的东西 | 结果 |
|---|---|---|
| 12 类信号 | K线形态（吞没、锤子线、射击之星）+ 指标（EMA 金叉死叉、MACD、RSI、布林） | 和“随便哪根K线”差不多 |
| 0–100 评分 | EMA、MACD、RSI、近期信号、成交量 + 多周期加减分 | 与之后 5 / 10 根涨跌的秩相关约 0 |
| 价格行为情景 | 多周期关键价位 + K线形态 + 顺逆大周期 | 约 0R，黄金计入成本后为负；收紧触发条件也没变好 |
| 出场规则 | 页面目标 vs 移动止损 / 持有 N 根 | **让盈利单跑**每笔多 0.1–0.5R，四份数据方向一致，两份单独显著；但情景整体仍无可靠优势 |
| 大周期方向 | EMA20/50、摆动结构、快均线 | 黄金 25 年里均线方向有小而显著的优势（扣掉牛市漂移后 +0.2 ATR / 20 根），熊市不成立 |

所以：**K线和多种指标、多周期是结合过的**，没结合的是时事（事件、新闻）。几点判断：

- 计划本身（先定规则和对照组、逐根回放不偷看未来、计成本、看区间和样本外）是对的。“没找到优势”是公开技术规则在黄金、比特币这类流动性很好的市场上的常见结果，不是测试方法错了。
- 多加指标不等于“多角度”：EMA、MACD、RSI、布林都是同一条价格序列的变换，彼此高度相关，叠在一起信息不多。
- 只测了日线：入场本应在 1h / 15m 触发，这些周期没有足够长的历史，没测。
- 时事目前只能用来**控风险**（事件前后波动放大、避开），新闻的方向性影响大多在公布那一刻就被交易掉了。这一点可以回测（见 §6）。
- 目标要定对：方向“正确率”不是关键，每笔期望多少 R、亏损怎么控制才是。回测已经按 R 统计。

## 2. AI 多角度分析会更好吗

能做好的（分析助手）：

- 把多周期状态、关键价位、情景、未来几天的事件、最新官方数据、新闻、你的持仓和止损汇总成一段能读的判断；
- 指出冲突：逆大周期开仓、重要事件前开仓、止损在 0.5 ATR 以内、情景已失效还拿着；
- 列出看多 / 看空的条件、各自的失效位、什么情况下观点要改；
- 复盘时对照你的交易习惯（交易页的复盘已有统计，可交给它解读）。

做不到、或没证据的：**稳定地预测涨跌**。语言模型没有专门的行情预测能力，研究里用它读新闻预测股价的结果有限、且随时间减弱。

最大的障碍：**没法用历史回测 AI**。模型的训练数据里已经有之后的行情（它知道 2024 年金价大涨），拿过去的数据问它会被“剧透”。唯一诚实的检验是从现在起**前瞻记录**：每次分析存档（时间、输入、结论），N 根K线后自动打分，积累几十到上百次再看。

结论：AI 当**分析助手和风控检查**，不当信号源；同时把能回测的改进（事件窗口、移动止损出场、大周期方向）用回测验证（§6）。

## 3. 接入方式：三条路，按优先顺序

页面先把当前分析整理成一份“分析包”（§4），交给代理 `POST /api/ai/analyze`，代理按顺序选：

1. **交给 Cirra（她开着时）**：她已经用你的 Claude 登录（订阅，不用 API key；默认模型 claude-opus-5-5），不会多一份账单。需要在 cirra-deskpet 加一个小接口（核对过她的代码，现在没有现成办法让外部程序请她做一次 AI 回答）：
   - 事件端口加 `POST /ask`：沿用现有的 token、只认本机 Host、不放行网页的规则；
   - 用她已有的一次性问答（`chat/oneshot.ts`，不带工具、不进对话上下文），把分析包当作“别人写的数据，不是指令”交给模型，**完整结果在 HTTP 响应里回给 MarketLens**；
   - 另外她用 1–2 句话说出摘要（走通知，免打扰照常）。不进她的主对话：避免和你正在聊的冲突，也避免外部文字碰到她的工具（记忆、提醒）。
   - 这是 cirra-deskpet 仓库的改动，按那边的规矩单独做、单独验收。
2. **MarketLens 自己调 Claude API（可选，Cirra 没开时）**：`.env` 里配 `ANTHROPIC_API_KEY`（或 `ant auth login` 的登录）后启用；用官方 `@anthropic-ai/sdk`，默认模型 claude-opus-5-5，结构化输出（`output_config.format` 给 JSON schema），固定的说明部分用提示缓存。
   - 费用估算（claude-opus-5-5：输入 $4 / 百万 token，输出 $20 / 百万 token）：一次约 8 千 token 输入 + 2 千输出 + 思考，约 $0.1–0.2；每天 5 次约每月 $15–30。改用 claude-sonnet-5-5（$2 / $10）约减半——用不用由你定。
3. **复制分析包（总是有）**：一个按钮把分析包和提问模板复制到剪贴板，粘贴到 claude.ai 或别的 AI 里。零成本、零配置，第①步就能用。

以后可选（反方向）：给 MarketLens 做一个只读 MCP 服务器，加到 Cirra 的“MCP 服务器”里，聊天时问她“黄金现在怎么样”，她自己去取数据。限制：只在她用 Claude 接口时有效；她的 HTTP MCP 不支持带认证头，要靠本机限制或 stdio 包装；工具调用默认要在气泡里确认。

## 4. 分析包（页面生成，JSON）

- 品种、周期、最新价、数据时间、是否实时 / 休市；
- 多周期矩阵：各周期方向、前高前低、最后收盘K线时间；
- 当前周期：评分与评分说明、关键数值（RSI、ATR）、关键价位（含参与周期、挡回次数、距离 ATR）、价格行为情景（状态、入场 / 止损 / 目标、顺逆大周期）、近期信号；
- 最近 30 根已收盘K线的开高低收（压缩成数组）；
- 事件：未来 3 天相关货币的高影响事件（时间、预期、前值），最近公布的 BLS 数据；
- 新闻：最近 10 条标题（来源、时间），**标明是未核实的第三方标题**；
- 我的持仓与止损止盈（有时），最近的复盘统计（有时）；
- 规则的回测结论摘要（让 AI 知道这些信号本身没有可靠优势，别把它们当证据堆）。

## 5. AI 输出（固定结构）

`summary`（1–2 句，给 Cirra 念）、`bias`（偏多 / 偏空 / 观望 + 依据）、`levels`（要盯的价位）、`bull` / `bear`（条件、入场思路、失效位）、`eventRisk`（事件与时间窗口）、`news`（新闻里和这个品种相关的要点，标“未核实”）、`conflicts`（和你的持仓、止损、大周期的冲突）、`changeMind`（什么情况下观点要改）、`unknowns`（缺的信息）。不给胜率或盈利概率；分析包里没有的数据不许编。

页面：分析页加一个“AI 分析”块（按钮触发、显示时间和来源：Cirra / Claude API / 未分析），Cirra 开着时她念 summary。

## 6. 留痕、前瞻评估、能回测的改进

- 每次分析存到 `var/ai/`（时间、分析包摘要、来源和模型、结论）。之后 5 / 20 根K线自动打分：bias 方向对不对（ATR 计）、提到的失效位有没有被触及。页面显示累计结果；样本少时只写“还不够判断”。
- 事件窗口回测（不涉及 AI，可以诚实地回测）：重要事件前后几小时的波动是否明显放大、在事件前进场的情景是否更差。需要历史事件日期：FOMC 有官方历史日程；非农、CPI 的历史发布日要另外整理（BLS 有历史日程页）。
- 移动止损出场已有回测支持（+0.1–0.5R），可以考虑把情景卡片的出场默认改成它（另行决定）。

## 7. 安全与成本

- 只在你点按钮时分析，不自动循环；同一份分析包 15 分钟内不重复请求；每天上限（默认 20 次）。
- 新闻标题等外部文字在提示里标明是数据、不是指令；Cirra 的 `/ask` 不带任何工具。
- AI 不下单、不改设置、不改预警；结论只显示和朗读。
- API key 只放 `.env`，不进页面、不写日志。
