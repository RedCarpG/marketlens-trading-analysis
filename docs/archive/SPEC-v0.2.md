# FinBot — XAU/USD 多周期分析工作台

版本：0.2；日期：2026-10-20（Europe/Paris）。状态：需求修订与开源选型，尚未实现。本文取代 archive/SPEC-v0.1.md 的产品范围；旧文件仅作历史，不作为并行规范。

## 1. 已确认需求与待定项

用户已确认：以 TradingView 中的 XAU/USD 为观察对象；周→日→4小时→1小时自上而下分析，通常不需要1小时以下周期；重要信号解释并提醒；提供有条件的多空入场时机建议；后续必须支持非农等重要经济日历与新闻分析；首版 Windows 本地网页，Telegram 可选，24/7 运维后置；只分析、不自动交易；优先复用开源成果，可拉取参考项目，允许将项目发布到用户 GitHub 私有仓库。

待定：TradingView 完整报价源代码、AI 是本机模型/云端 API/手动 ChatGPT、行情及 AI 总预算。这些答案到达前，不选择付费数据套餐、不下载模型、不接入真实凭据。

变更：移除旧版15分钟触发、Telegram必需、首版24/7验收；保留确定性计算、历史可追溯、来源引用和故障降级。首版包含技术情景与重要信号；经济日历和新闻为明确的后续阶段，尚未接入时网页必须显示“未覆盖”，不能显示“近期无风险”。

## 2. 分析方法与输出

多周期提供相互制约的背景，不代表周线能唯一推导日线或小时线。涨/跌/震荡/数据不足均是有效输出，周期冲突时允许观望。不能把规则分数或语言模型自信程度包装成经校准的胜率。

| 周期 | 职责 | 首批证据候选 |
|---|---|---|
| 周线 | 长期结构、主要支撑阻力、核心情景 | 已确认结构高低点、EMA20/50、ATR14 |
| 日线 | 判断顺势延续、回调或结构冲突 | 日线结构、与周线关键区关系、波动幅度 |
| 4小时 | 候选入场区域与形态形成 | 突破/回踩/反弹受阻、最近确认结构 |
| 1小时 | 确认或取消候选情景 | 已收盘突破/跌破、回踩确认、失效条件 |

以上指标不是已验证策略。周线至少应有250根完整样本供EMA暖机与背景观察；每周期要求明确的历史最小长度，历史不足不降低阈值冒充完整分析。结构拐点若需要右侧K线确认，只能在右侧线收盘后确认，回放不得回填成此前已知。

每条情景必须包含：截至时间、报价源、各周期状态、做多或做空方向、入场观察区间、触发条件、失效/参考止损位置、目标区域、有效期、当前状态、冲突证据、事件风险与来源。状态为观察中→已触发→失效/到期；失效消息也应提示。报价过期、事件状态未知或周期证据冲突可抑制触发。

点位来自可追溯的本地行情和规则，AI负责解释与提出可验证的备选情景；AI提出的新点位先校验价格口径、结构证据和多空方向，未经验证不作为可触发情景。多头必须满足参考止损<入场<目标，空头相反；成本未知时风险收益只能标为未计成本估算，不输出仓位或杠杆。

示意逻辑：周线偏多、日线回调→观察4小时支撑区→等1小时确认后激活做多情景；若日线破坏主要结构则撤销原情景，转为观望或另建空头情景。不能强制所有周期一致，也不能仅因大周期偏多就持续提示买入。

## 3. 本地网页体验

首页展示：报价源/数据时间/连接状态；周日4h1h状态矩阵；可切换周期K线与关键价格区域；主情景/反向情景/观望原因；事件日历与最新新闻（未接入时明确标注）；提醒历史与分析证据。默认中文、Europe/Paris展示，保留原始时区。

用户可刷新分析、查看每个点位的来源、调整监控与通知开关、查看AI模式和费用、导出结构化分析摘要。网页内提醒为必需，Windows通知为可选开关，Telegram为后续可选适配器。关机/程序未运行时不承诺提醒；首版不自动常驻。

## 4. 架构与依赖

建议：Python分析服务 + SQLite + 本地网页 + TradingView Lightweight Charts。HTTPX负责外部请求，pandas/NumPy负责计算，Pydantic校验配置与数据；web服务候选FastAPI，前端可用TypeScript，正式版本与打包方式在技术验证阶段锁定。只监听127.0.0.1，不发布网站。

数据流：授权行情→校验/周期边界处理→本地特征→多周期情景引擎→数据库/网页提醒→可选AI解释。日历与新闻作为独立输入，不与行情故障耦合；AI不可用时仍显示确定性事实，不伪装已完成AI分析。

数据库保留candles、features、scenarios、alerts、events、news、ai_reviews与runtime_state。情景记录规则版本、配置散列、每周期输入截至时间；提醒唯一键为情景ID+状态转换+渠道；AI按输入散列缓存。数据修订保留历史版本；数据/解释/提示词均可追溯。

候选AI模式：本地模型服务器、云端API、手动导出摘要。用户尚未选定；不把桌面应用运行误称为模型离线。OpenAI官方提供gpt-oss本地运行教程，但需检查硬件和实际中文分析质量；不直接假设能运行某模型。采用固定字段输出、数值核对、超时、预算限制及明确的“分析失败”状态。

## 5. 行情源与周期一致性

TradingView是用户看图入口，完整代码尚待确认。官方当前没有供用户获取行情/指标的通用API；图表库本身不附送行情。不可用GC期货、ETF或代币报价替代XAU/USD。非官方抓取不作为可靠主源。

候选为匹配报价源的授权API或Twelve Data；OANDA等券商API须核实账户地区、XAU权限与数据使用条款。不同报价源的点位不应无提示复用。正式选源前比对同时间段OHLC、价格口径bid/ask/mid、点差、收盘和周界线；无法匹配时网页注明差异，禁止称为“与TradingView完全一致”。

使用供应商会话日历与日/周收盘规则；UTC作为存储格式，但不得把UTC午夜直接等同用户图表的日线边界。未完成的周/日K线可展示为暂态，不能冒充已确认趋势。1h数据不意味着只需要几个月历史：周线长历史与小时数据可分周期拉取，必须来自相同可比来源。

只对已确认K线触发规则；缺失/延迟暂停相应情景，无前值填充伪造K线。历史恢复数据不得推送为刚发生机会。检测刷新可比1小时更频繁，但不因此加入1小时以下分析策略。

费用核查：Twelve Data页面有不同额度和结算选项，同一价格页不同抓取显示过Grow起价$29及选定额度月付$79，不能把任一数字当作本项目确定成本。先取得XAU所需权限、历史深度、展示/机器分析/云处理许可与实际结算报价。AI、数据、新闻许可分别核算；预算待用户回答，无付费操作授权。

## 6. 经济日历与新闻（后续必做）

先做可核验的计划事件：非农、CPI、FOMC；再扩展重大新闻。非农使用BLS公布的日历而非硬编码“每月第一个周五”；FOMC以美联储日历为准。建议提前24小时/1小时提醒，发布后标记等待数据/已核验，并记录日程变更。官方日历通常不提供市场一致预期，缺少预期值时不得声称超预期。

存储scheduled_at、published_at、received_at、source_url、revision、actual、consensus及其来源；统一UTC存储、巴黎时区展示，测试美国与欧洲夏令时错位周。经济数据发布前后的情景触发抑制窗口为待回放的配置项，不能盲目把非农利好美元映射为黄金必跌。

已安排事件可提前提醒；突发新闻只能在被来源发布且系统收到后提醒，不能承诺提前知道。新闻包含来源、发布时间、获取时间、确认程度及影响解释；相似消息去重，传闻与正式公告分开。新闻源及许可待选，不承诺秒级覆盖。文字是不可执行输入，不能改配置或触发交易。

## 7. 开源复用决策

优先组合成熟组件，避免把大型交易框架的全部功能带入首版：

- Lightweight Charts：推荐作为网页图表层，Apache-2.0；保留LICENSE、NOTICE及TradingView署名链接。需自行接数据和实现分析交互。
- TradingAgents：参考技术/新闻解读、多空情景、模型适配；已拉取只读研究副本，未安装或运行。其默认配置使用股票数据和公司基本面，黄金需单独适配；首版不接其交易决策执行链或投资组合逻辑。整套多代理调用不默认启用。
- OpenBB ODP：数据连接备选；当前页面说明Apache-2.0且仓库跳转到openbq-org/OpenBB。它不是免费黄金数据许可或已完成的本地工作台。采用前固定确切版本并复核许可与维护来源。

详见OPEN_SOURCE_REVIEW.md。任何正式引入需记录commit/version、许可证、NOTICE、修改文件与理由。私有仓库仍须保留第三方许可和署名。

## 8. 阶段与验收

| 阶段 | 交付与验收门槛 |
|---|---|
| P0 选源与模式 | 确认完整图表代码、预算、AI模式；取得周/日/4h/1h样本，核对会话边界与历史长度；不足则仅离线演示 |
| P1 本地分析工作台 | 四周期图表与证据、主/反向/观望情景；同数据配置可复现；未来数据不能改变历史信号；当前周未收盘、缺线与周期冲突都有测试 |
| P2 提醒及AI解释 | 情景触发/失效提醒、数值来源；AI失败不阻断基础结果；重复刷新不重复通知；重启恢复不会推送旧机会；所选AI模式实测 |
| P3 日历与新闻 | 非农/CPI/FOMC时间可核验、提醒去重、日程修订、夏令时测试；新闻区分发布时间与接收时间，实际/预期缺失不编造 |
| P4 后续常驻运行 | 自启动、健康监督、备份恢复、预算告警；连续7日覆盖交易与休市；断电/断网能力边界明确；Telegram可选 |

回放使用时间顺序留出区间；记录信号数、观察期限、触发率、失效率及有利/不利波动。模拟结果必须注明成本与同根K线内先后顺序不明的处理方式；没有足够证据不称有盈利优势。首版成功指标是数据和逻辑可靠、解释可追溯，不是预测必胜。

## 9. 安全与操作

仅行情读取；不增加订单、仓位或杠杆接口。私钥、token、完整账户信息不进入网页前端、日志、Git或AI输入。新闻、行情及模型输出均视为不可信数据；本地服务设置来源校验，配置写接口避免跨站请求。

第三方参考源码只在work/references保存，排除Git上传；本次未执行安装脚本。后续引入经审查的组件，不运行未知交易功能。密钥使用系统凭据或受限文件；数据许可控制上传AI的范围。

SQLite使用事务、在线备份及恢复演练；日志建议30日、情景审计90日，行情保留按许可调整。数据过期、模型不可用、行情额度耗尽、日历未刷新均在网页显式显示。首版退出即停止，常驻运维后置。

规划目录：docs/（SPEC、CONT、开源选型与运维）；backend/（providers、analysis、scenarios、events、ai、storage）；frontend/；tests/fixtures/；var/（不入Git）；work/（研究副本，不入Git）。本次仅文档和参考源码。
