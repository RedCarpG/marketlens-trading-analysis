## 2. 产品边界

- 默认标的为 XAU/USD 现货黄金报价，单位 USD/金衡盎司；实施前用供应商元数据确认。券商 CFD、COMEX GC 期货、黄金 ETF、PAXG 等不是同一标的，不可拼接或暗中替代。
- 建议首版使用 15 分钟已收盘 K 线触发、1 小时已收盘 K 线判断背景；先做趋势、突破和波动异常，不训练预测模型。
- 运行 24/7 指进程与健康检查持续工作；黄金交易时段、节假日和维护暂停依数据源日历，不能按虚拟货币的全年连续交易处理。
- 输出为事实、条件式解释、反向情景与观察失效条件。指标分数不称为上涨概率，不承诺预测准确率或盈利。
- 不建立订单、自动调仓、仓位管理或交易执行模块；不读取个人持仓、银行流水及其他项目资料。首版不接新闻抓取、复杂代理框架、向量库或模型训练。

## 3. 技术架构

```text
行情 REST API → 数据适配器 → 校验/收盘确认 → SQLite K线
                                           ↓
                              本地指标 → 规则/状态变化
                                           ↓
                              事务写入信号与通知 outbox
                                 ↙                   ↘
                    确定性事实通知               重要信号队列
                    Telegram / 桌面             云 AI → 校验 → 补充解释

调度/恢复、结构化日志、预算计数、健康检查贯穿全流程
```

单机单进程核心、独立通知适配器与有界 AI 工作队列即可。用 Python 标准库 asyncio 实现轮询及任务取消；SQLite 负责持久化，不引入 Redis 或 Kubernetes。AI 超时不能阻塞基础信号提醒。

行情接口定义 fetch_candles(symbol, interval, since)、instrument_metadata()、market_status()；未知市场状态必须显式返回 unknown。AI 接口只接收结构化快照，通知接口接收固定 message_id 与内容。适配器只能调用批准的行情读取端点，不提供订单接口。

存储设计：

| 表 | 必需信息与约束 |
|---|---|
| candles | provider、instrument、price_type、timeframe、open_time_utc、close_time_utc、OHLC、可空 volume、complete、received_at、质量状态；来源+标的+价格口径+周期+开盘时间唯一 |
| signals | signal_id、bar_close、规则版本、配置散列、输入快照散列、条件与指标值、方向、级别、有效期 |
| outbox | signal_id+channel+message_kind 唯一；pending/sent/retry/expired、重试时间、远端消息 ID |
| ai_reviews | signal_id、输入散列、模型标识、提示词版本、输出、校验结果、token 用量与估算费用 |
| runtime_state | 最后成功收盘、去重/冷却状态、心跳、预算、schema_version |

全部持久化时间用 UTC，展示默认 Europe/Paris 并注明时区。采用事务和单写入者，避免一条信号写入成功而通知任务丢失。数据库备份必须使用 SQLite 在线备份或停写快照，不能只复制运行中的主文件而漏掉 WAL。

## 4. 数据质量与可复现规则

默认每 60 秒检查新收盘线；按供应商延迟留出 30 秒收盘宽限，若接口提供 complete 标志则同时要求为真。单一来源获取 15m 数据，并按 UTC 整点从四根完整 15m 聚合 1h；遇缺线不得生成完整 1h。若改用供应商原生 1h，须记录边界与聚合差异。

检查时间递增、重复、未来时间、OHLC 高低关系、正价格及数据陈旧程度。开市期间，预期收盘后超过 120 秒未到线标为 stale，暂停新市场判断，发送一次数据故障通知；此阈值须与购买的数据延迟匹配。休市不判为故障。不得用前值填充伪造 K 线，不把 tick volume 当真实全市场成交量。

建议默认规则（均须回放检验，非已证实的交易优势）：

- 指标：EMA20/50、RSI14、ATR14、前 20 根 K 线高低点。EMA 使用 alpha=2/(n+1)，以首 n 根均值初始化；RSI/ATR 使用 Wilder 平滑。明确 RSI 平盘/零损失边界；至少 250 根有效 1h 暖机，遇非休市缺口暂停并重建受影响窗口。
- 上行突破：15m 收盘价高于前 20 根最高价加 0.2×前一根 ATR14，且最近已收盘 1h EMA20>EMA50。下行条件对称。当前线不参与自身突破阈值。
- 波动异常：当前真实波幅 > 2×前一根 ATR14；与突破同根发生时合并展示。RSI 首版只提供上下文，不独立生成买卖指令。
- “重要信号”：首次进入有效突破状态、突破方向反转，或突破同时出现波动异常。纯波动异常只发送本地规则结果，不默认调用 AI。
- 按 source+symbol+timeframe+bar_close+rule_version 生成信号 ID；同规则同方向冷却 60 分钟，反向有效突破允许打断。必须先离开触发状态再重新进入，不能在条件持续成立时逐根重发。

历史补数只更新计算和审计；超过 30 分钟的事件标记 historical，不当成当前机会推送。源数据修订保留修订痕迹；回放可复现当时输入，不能悄悄改写历史提醒。备用源首版只用于人工比对；切换需重新暖机并标注来源，不拼接 K 线。

建议预算：行情按满足权限的实际报价；云 AI 暂设 $5/月应用硬上限、每天最多 10 次、每次最多约 2,000 输入与 600 输出 tokens。这是配置建议，不是模型报价。费用公式为输入 tokens×输入单价+输出 tokens×输出单价，另计供应商特殊计费项目；实际模型和单价在实施时核实并锁定。预算满或费用未知即跳过 AI，不停止本地分析。Telegram 普通低频通知以标准 Bot API 为基础，不启用付费广播；电费、网络和未来主机另计。本次不创建密钥或订阅。

## 7. AI 与通知行为

AI 输入仅含来源、标的、截至时间、已收盘指标、规则证据、有限 K 线摘要和质量标志；不上传密钥、账户 ID、个人持仓或整库。行情许可须允许所选云处理方式，否则只传可许可的衍生摘要或禁用云解释。

要求结构化输出：facts、interpretation、bull_case、bear_case、invalidation、uncertainties。事实数值与本地输入比对；缺失信息明确写未知，不允许编造新闻、价格或胜率。AI 无工具执行权限，不能改阈值、决定是否发基础通知或产生订单。20 秒超时，最多一次受预算约束的重试；JSON 不合法或数值冲突时舍弃解释并记录原因。

基础通知先发，包含信号 ID、XAU/USD/来源、周期、收盘时间、事实指标、触发条件、数据状态与失效条件。AI 成功时以同一 ID 补充解释；AI 失败仅注明未生成。事实与解释明确分栏。

Telegram 仅发允许的 chat_id；用户先启动 bot，再完成目标验证。桌面通知只在用户交互会话可用时保证尝试展示，勿扰模式可能抑制显示；后台服务不能假设能直接弹出通知。每渠道独立记录结果和重试；429 遵循 retry_after，网络故障指数退避并有总时限。远端已接受但本地未确认时可能重复，不能承诺跨网络 exactly-once；固定信号 ID 便于识别。

| 阶段 | 交付 | 可测验收标准 |
|---|---|---|

试运行同时评估告警数量、1h/4h 后方向变化、最大有利/不利波动与样本量，并对训练/调参区间和留出区间分开报告。没有真实成交数据时不报告已实现收益；任何假设收益需计点差、滑点与费用。不以回测好看作为上线依据。

## 10. 安全与运维

- 密钥放 Windows 凭据管理器或受 ACL 限制的本地秘密文件，由运行账户加载；.env、DB、日志、备份均不入 Git。日志必须遮盖 Telegram URL 中的 bot token、Authorization 与查询参数密钥。
- 能使用只读权限就使用只读；若供应商 token 本身具交易权，则应用端只允许已批准的行情路径，不以“代码没调用交易”声称凭据天然只读。首版优先不带券商交易权限的数据供应商。
- 首版仅出站 HTTPS，不开放公网端口。AI 返回值和远端内容按不可信数据处理，禁止 shell 执行或写配置。
- 开发期前台运行；24/7 阶段采用 Windows 任务计划开机启动核心、失败重启与单实例锁。桌面 helper 在用户登录后启动；核心即使无人登录仍可向 Telegram 发信。
- 防止睡眠、安排 Windows 更新维护窗口并验证重启恢复；本次不改变电源或系统设置。家用电脑断电、断网时不能保障服务，未来可迁往常开小主机；异地运行时桌面 helper 需单独设计。
- 每60秒本地心跳，5分钟未更新视为故障。独立监督任务检查核心退出；整机断电需要独立外部心跳接收方才能发现，首版若未配置需明确不可检测，不能让故障进程负责报告自身死亡。
- 保留运行日志30日、信号/AI审计90日作为初始建议；行情保留期受许可限制。每日备份、保留7份并每月恢复演练；备份加密和访问权限与原库一致。磁盘不足停止写入并告警，不能无限扩张日志。
