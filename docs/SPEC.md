## 1. 目标与范围

个人自用的行情观察与分析工具：观察K线并叠加常用技术指标；自动识别信号，给出入场时机评分和参考的入场、止损、目标位；支持预警（下一步实现）。

分析方法为**自上而下的多周期分析**：从大周期（月线、周线）判断背景和关键位，逐级推导到日线、4小时，最后在1小时/15分钟上寻找入场时机。详见3.5节。

品种优先级：**黄金期货 GC** 为主，之后扩展到美股和货币（外汇，必要时加密货币）。用户日常使用eToro和TradingView，后期接入实时行情接口。只分析、不下单：只使用只读行情接口，不接入任何交易、仓位或账户写操作。

### 3.1 数据适配层约定

每个数据源是 `AD` 对象中的一项，实现两个方法并统一返回标准化K线：

```js
// 标准K线
{ timestamp: 毫秒时间戳, open, high, low, close, volume }

history(item, tf)                    // 返回K线数组（旧到新）
subscribe(item, tf, cb, bars)        // 每次有更新调用 cb(bar)，返回取消订阅函数
                                     // 同一timestamp表示更新当前K线，新timestamp表示新K线
```

- `item` 来自自选列表 `WL`：`{ sym, name, src, p(价格小数位), grp(左侧分组), base(仅模拟用) }`
- 新增品种：往 `WL` 里加一项并指定 `src` 和 `grp`；新分组名加到 `GRPS` 决定顺序
- 新增数据源：往 `AD` 里加一项，实现上述两个方法

### 3.2 eToro代理（已实现）

`server\`（Node.js，依赖 ws 8.18.0），`npm start` 后访问 http://127.0.0.1:8787/。页面的eToro适配器调用：

- `GET /api/etoro/candles?symbol=&interval=&count=` → 标准化K线数组，周期15m/1h/4h/1d/1w/1M
- `WS /api/etoro/stream?symbol=&interval=` → 推送标准化单根K线

2026-10-22对照 api-portal.etoro.com 核实：

- 基础地址 `https://public-api.etoro.com`；请求头 `x-api-key`、`x-user-key`、`x-request-id`（每次唯一UUID）
- `GET /api/v2/market-data/instruments?symbols=...` 精确换取 `instrumentId`（v1 search为前缀匹配且分页，查不到GOLD；GOLD=18）
- K线：`GET /api/v1/market-data/instruments/{id}/history/candles/{asc|desc}/{interval}/{count}`，interval 最大到 OneWeek，**没有月线**；单次最多1000根，只能取最近N根
- 月线由代理合成：近期由日线聚合，更早的由周线按周起始日归月（跨月周有偏差）
- 实时：`wss://ws.etoro.com/ws` 订阅 `instrument:<id>`（Bid/Ask/LastExecution，约每秒一条），代理据此推进当前K线。文档称无需鉴权，实测必须先Authenticate
- 限速：市场数据接口共享每分钟60–120次，代理按周期缓存
- 本地K线存储（2026-10-24）：eToro 只给最近1000根且不能往前翻页，代理把每次拉到的K线按时间合并存到本机 var/candles/<instrumentId>/<interval>.json（同一时间点以新数据为准，先写临时文件再改名；var/ 不入Git），历史随使用时间增长；/api/etoro/candles 返回合并后的序列，单次最多5000根，页面取3000根；月线由更长的日线合成。代理启动1分钟后及之后每6小时把已存过的品种/周期再拉一遍（间隔1.5秒），避免长时间不开页面时短周期断档（15m 的1000根约覆盖10天）。GET /api/store 列出各周期已存根数与起止时间，设置菜单显示
- 页面eToro品种为 `GOLD`（跟踪黄金的CFD），**不是GC期货**，比Micro Gold期货低约14美元。eToro有Micro Gold期货（如GOLD.DEC26），价格同GC、有成交量，但单个合约历史短，需拼接连续合约才能做大周期

详见 server/README.md。

### 3.3 信号引擎

`analyze(bars)` 返回 `{ sigs, s(评分), dir, c, a(ATR), rsi, hi, lo }`。

评分规则（基础分50）：EMA20与EMA50位置±10；收盘价与EMA50位置±5；MACD柱正负±8；MACD柱增减±4；RSI偏强偏弱±4，极端区间修正±6；最近5根内的信号每个±6（上限±18）；放量时按当根涨跌±4。结果限制在0–100。

无成交量的数据源（最近100根成交量全为0，如eToro GOLD CFD）：放量项不计分，VOL副图自动移除并禁用，面板注明“成交量：无”；切回有成交量的数据时按用户原先的VOL开关恢复。其余各项均为加减分，以50为中心，缺一项不需重新缩放。

这是简单的规则打分，权重和阈值未经调整。初步回测（docs/BACKTEST.md 第 12–13 节，黄金 2001–2026 与比特币 2018–2026 日线）显示评分与之后 5 / 10 根涨跌几乎无关（秩相关约 0），暂无可调的方向。评分不是胜率，界面与文档不得将其表述为盈利概率。

### 3.3.1 关键价位与图上标注（2026-10-22）

- 关键价位 `levels()`：取当前周期及所有更大周期已确认的摆动高低点（左右各2根，且拐点前10根内摆幅≥1 ATR、之后≥0.5 ATR，过滤小波动），只保留当前周期最近150根K线高低范围±1 ATR内的；以每组第一个点为基准、0.5 ATR（当前周期）内的合并，代表价取其中周期最大的点，标注参与的周期（如“1M·1w·1d”）。`touch` 为最近150根中在该价位被挡回的次数（影线触及0.25 ATR内但收盘在另一侧，相隔不足3根算一次）。
- 关键价位判定 `isKey`：多个周期共振，或被挡回≥3次，或来自比当前更大的周期。
- 主图横线（“支撑阻力”开关）：每侧按距离取最多3个关键价位，彼此至少相隔0.75 ATR；若其中没有更大周期的价位，用4 ATR内最近的一个替换最远的那个。支撑用涨色、阻力用跌色；周线/月线级别线宽2，低于当前周期的虚线；右侧标注周期、类型、价格。（2026-10-22 调整：原规则在周线上每侧画5条，不少是只出现一次的小拐点）
- 信号箭头（“信号箭头”开关）：最近80根已收盘K线内，金叉/死叉/布林突破总是标出，其余信号只在距关键价位（isKey）0.5 ATR内时标出（文字加“·支撑/·阻力”）；同一根K线同方向合并为一个箭头，最多8个。
- ~~计划线~~（2026-10-22 移除：原ATR+价位的通用计划实用性低）→ 改为下述“价格行为情景”，“情景线”开关只画仍有效的情景（触发K线箭头 + 入场/止损/目标线，标签在左侧）。
- 价位按**最新价**（含未收盘K线）划分支撑/阻力并选取，范围也包含最新价（2026-10-22修正：原按上一根收盘价，日线当天大跌120时画出的“支撑”全在现价上方）。参考计划仍按已收盘K线计算。
- 前高/前低（“前高前低”开关，2026-10-22）：每个周期中时间上最近、仍在最新价上方的摆动高点为前高，下方的摆动低点为前低；比它更近但已被突破/跌破的记为“已突破/已跌破”。周期矩阵的“前高/前低”两列显示所有周期（价格、形成时间、距最新价百分比，没有则显示“近期新高/新低”）；主图画当前及更大周期的前高/前低，月线/周线线宽2。
- 多次挡回区间：主要价位中被挡回≥3次的画成半透明区间（合并点的价格范围，至少±0.15 ATR），标签注明“挡回N次”。
- 同侧相距0.3 ATR以内的标注合并为一条，标签拼接（如“1d前低 4018.91 · 1d 支撑 挡回6次 4023.47”）。
- 参考计划的入场/目标改为使用含上一级或更大周期的合并价位，与图上线一致；范围内没有时退回上一级周期自身高低点，再退回ATR估算。目标取越过入场区1 ATR以外最近的反向价位。
- 面板新增“关键价位”列表，显示价格、参与周期和距收盘的ATR倍数。只在品种、周期、主题或价位变化时重绘标注。

### 3.3.2 价格行为情景（纯K线，2026-10-22，取代参考计划）

`scenarios()` 在当前周期最近的关键阻力（R）和支撑（S）上各给两个条件情景：阻力处“触及出现滞涨K线 → 做空”与“收盘突破后回踩不破 → 做多”；支撑处“回踩出现止跌K线 → 做多”与“收盘跌破后回抽不过 → 做空”。最近的阻力与支撑相距不足0.5 ATR时视为价格处在区间内，合并为“区间”卡片（站上上沿做多 / 跌破下沿做空），并顺延给出外侧的阻力与支撑。

- 触发（多头，空头对称；2026-10-25 收紧）：最近6根已收盘K线中，有K线最低价触及支撑0.25 ATR内、收盘仍在支撑上方，且为止跌形态（下影≥K线长度40%，或看涨吞没；原来的“阳线收在上部40%”已去掉）；价位须为大周期价位（代表价来自比当前周期更大的周期，如日线只用周线/月线的摆动点；本周期自己的价位仍显示，但条件情景标为“只作参考”）；同一价位同方向前10根内已出现过符合条件的K线时不算新触发（冷却，仍显示原来那次）。收紧选项在 `SC_DEF`（web/js/core/scenarios.js），收紧前相当于 `{ loose: 1, htf: 0, cool: 0 }`。此前20根内曾收盘跌破该价位 → “突破回踩”（前阻力转支撑）；最低价刺破价位 → “假跌破”；否则 → “支撑反弹”。
- 入场=触发K线收盘；止损=触发K线极值与价位外0.25 ATR；目标=下一个反向关键价位，不足1倍风险时用2倍风险。
- 状态：已触发 / 失效（之后K线触及止损；最新价越过止损为“失效（未收盘）”）/ 已到目标 / 被反向触发取代（多空同时触发时以较新的为准）。
- 每个情景标注“顺大周期/逆大周期”（相对多周期结论的方向）。参考依据：常见价格行为方法中的关键位反转K线、假突破（SFP）、突破回踩。初步回测（docs/BACKTEST.md 第 13 节）：情景整体约不赚不亏，“顺大周期”的优势来自牛市做多，熊市里不成立。收紧后（第 14 节）触发天数从约 65–79% 降到 7–11%，平均 R 仍约为 0，计入成本后为负：收紧只减少了噪音和成本，没有带来优势。

- 关键价位、价格行为情景也可点击高亮（2026-10-24）：价位加粗横线标出，不另外标K线，而是缩放到本周期上一次触及它的K线（影线在0.25 ATR内，跳过最近5根）和最新K线同在画面里（约占可见区域80%），对照当时和现在；情景有触发时竖条标出触发K线、从触发K线起画入场（实线）/止损（橙色虚线）/目标（虚线）并定位，没有触发时按价位处理（区间卡片标出上下沿）。规则同信号/交易：再点取消，Esc 或选中项提示的 ✕ 取消。
- 高亮定位（按可见区域的实际像素计算，2026-10-24 调整为略偏右）：在可见区域8%–80%内则不滚动；超出左侧 → 放到62%处（中间偏右）；超出右侧 → 放到70%处；交易开平仓跨度超过半屏时中点放到60%；靠近数据末尾时以能滚到的为准。
- 选中交易时自动缩放（2026-10-24）：定位范围为开仓到平仓（持仓为开仓到最新K线），目标约占主图宽度35%；每根K线不超过14px（很短的交易不放得过大），一般不小于2.5px，很长的交易在2.5px时仍超过宽度60%的继续缩小（最小1px）到占60%。当前缩放与理想值相差不到1.6倍时不缩放、只按上一条平移，避免在时长相近的交易之间来回缩放。缩放时交易中点放到62%处（中间偏右），靠近最新K线时最新K线至少在78%处；缩放与平移约0.36秒同步过渡，拖动、滚轮、取消选中或切换周期时停止。点“选中项”提示的文字会按同样规则重新定位。信号仍只平移不缩放。
- 右侧面板分块（2026-10-22）：可折叠块的开合状态记在本地（默认展开）。每块标题右侧放对应的图上标注开关（情景、前高前低+支撑阻力、信号箭头），与顶栏“标注”菜单同步；点开关只切换图上标注，不会开合块。2026-10-24 起分为“分析 / 交易 / 预警”三个标签页，见 3.3.8。

### 3.3.5 标注的视觉规则（2026-10-22）

每类标注用不同的“线型 + 形状 + 标签样式”区分，虚线只留给止损/止盈；参考 TradingView 的多空仓位工具、券商持仓线和价格标签避让做法：

| 类别 | 图上画法 | 标签 |
|---|---|---|
| 支撑阻力 | 贯穿实线，周线/月线1.5px，低于当前周期的半透明；挡回≥3次为半透明区间 | 纯文字（半透明底） |
| 前高前低 | 从形成K线起向右的点线射线，起点 ◆；与支撑阻力重合时只画 ◆ | 纯文字，前缀 ◆ |
| 信号箭头 | 小三角（涨/跌色），文字弱化色 | 箭头下/上方 |
| 情景 | 从触发K线起的盈亏框：目标一侧涨色框、止损一侧跌色框，入场实线 | 框内空心标签（类型·盈亏比）；右侧入场/目标/止损空心标签 |
| 我的已平仓 | 买=蓝▲（价下）、卖=橙▼（价上），开平仓之间按盈亏着色的实线，平仓空心圆；开平仓的时间×价格范围铺约11%不透明度的盈亏色 | 实心盈亏标签 |
| 我的持仓 | 粗实线（买蓝/卖橙）+ 开仓三角；开仓价到最新价之间、从开仓K线到右边缘铺约13%的盈亏色（浮盈涨色/浮亏跌色）；我的止损/止盈为从开仓K线起的点划线（独有线型），起点有 SL/TP 实心小标记，并用竖线从开仓价连到止损/止盈价 | 持仓实心标签（按浮盈着色）；止损/止盈实心标签，附触及时的大约盈亏（价差×数量，未计费用） |
| 布林带 | 紫色：上下轨虚线、中轨实线，上下轨之间铺约7%不透明度的淡紫底（自定义 draw 回调，先画底再画线） | — |

指标配色（2026-10-23）：图表库默认让所有指标共用同一套5色（MA5、EMA20、布林上轨同为橙色），改为每个指标一个色系+线型——MA 暖橙系细线（周期越长越深越粗）；EMA(20,50) 青色系1.8px；布林紫色（见上）；MACD 的 DIF 青/DEA 橙；RSI 只用14（与分析一致）紫色，30–70 区间淡底+虚线；KDJ 橙/青/洋红。“指标”菜单每个按钮前有对应配色小样。

主图价格轴只按K线计算（2026-10-24）：图表库默认把主图指标线的数值也算进价格轴范围，开关布林带（上下轨超出K线高低点）时整个主图会突然压缩/拉伸；MA60、EMA50 远离价格时也一样。改为 MA / EMA / BOLL 不参与价格轴缩放（同 TradingView“仅按价格缩放”）：这三个指标的线和左上角图例数值由页面自己绘制，计算公式与图表库 9.8 一致（已逐值核对相同）；超出价格轴的部分被主图上下边缘截断。开关这三个指标时K线位置不变。

- 右侧所有价位标签由一个标签层统一绘制：按价格排序，相邻至少相隔18px（2026-10-24 起标注文字 13px、信号与 SL/TP 小字 11–12px；先向下推、超出底部再向上收），被推开的用细线连回原价位，缩放平移时实时重排。
- “标注”菜单每个开关前有对应图例。滚动条为6px细条，平时透明，鼠标移入栏内才显示。

### 3.3.6 价格预警（2026-10-24）

右侧“预警”页：顶部总开关；三类提醒各一个开关；显示系统通知权限状态与最近10条预警（按类型着色）。不在预警页时，新预警在“预警”标签上计未读数；开着且无未读时标签上为呼吸圆点。设置记在本地，上次开着预警时打开页面自动进入实时模式。

- 范围：只监控当前品种和周期；需页面保持打开。开启时申请浏览器通知权限（必须由点击触发），并自动打开实时行情；每次刷新（实时约每300ms）检查一遍。
- 关键价位：所有关键价位（isKey，不只图上每侧3条）进入 ±0.15 ATR 时提醒，离开0.5 ATR后重新布防。
- 情景：出现新的“已触发”，以及已触发 → 失效/已到目标/被反向触发取代时提醒。
- 我的止损/止盈：价格进入0.5 ATR以内提醒（附相距ATR倍数与触及时的大约盈亏），离开1 ATR后重新布防；只看离现价30%以内的止损止盈。
- 去重与基准：每个提醒有布防状态；第一次见到时若已在范围内则不提醒（作为基准）；切换品种/周期或改勾选时清空状态重新建立基准，避免一开启就被已有状态刷屏。
- 提醒方式：页面右下角弹出提示（按类型着色，10秒消失，可点关）+ 系统通知（已授权时）+ 记入最近预警。通知被浏览器拒绝时只在页面内弹出。

### 3.3.7 交易复盘（2026-10-24）

“交易”页工具栏的“复盘”按钮打开复盘面板；点明细里的一行会关闭面板、在图上高亮这笔交易并在“交易”页选中它；纯计算在 web/js/core/review.js（reviewTrade / summarizeReviews），界面在 web/js/review-ui.js。

- 逐笔：只用开仓那一刻之前已收盘的K线（各周期最多最近 600 根），按与实时分析相同的规则（ctx / analyzeMTF / scenarios）重算当时的结论；入场周期取 1h / 4h / 1d 中开仓前已有 ≥100 根已收盘K线的最小一个。
- 每笔给出：大周期方向（顺势 / 逆势 / 震荡）；入场位置（做多时支撑在 0.5 ATR 内为“靠近支撑做多”，阻力在 0.5 ATR 内为“顶着阻力做多”，做空对称，其余“价位中间”）；止损距离（ATR 倍数；离开仓价超过 30% 视为 eToro 默认远端止损，按“未设”；<0.5 过紧，>3 过宽）；结果 R 倍数（有止损时）；当时是否有同向情景已触发；持仓时长。
- 汇总：只统计已平仓的交易；按大周期方向、入场位置、止损设置、价格行为情景分组列笔数、胜率、净盈亏；“值得注意”列出每个维度里净亏最多（≥2 笔）的一组及其占全部亏损额的比例、最赚钱的一组、亏损单是否拿得明显更久、没设有效止损的笔数。
- 持仓中的交易列在明细里，但不计入统计。点明细中的一行：关闭面板并在图上高亮这笔交易。规则未经回测，只用于反思交易习惯。

### 3.5 多周期自上而下分析（已实现初版，仅模拟数据验证）

目标周期：1M / 1w / 1d / 4h / 1h / 15m。分析顺序固定从大到小，上一级的结论约束下一级，而不是各周期单独打分后取平均。

| 层级 | 周期 | 职责 | 输出给下一级 |
|---|---|---|---|
| 背景 | 1M（可选）、1w | 长期趋势方向、主要支撑阻力 | 方向偏向（多/空/震荡）、主要关键位 |
| 结构 | 1d | 判断顺势延续、回调还是与大周期冲突 | 是否允许顺势、回调目标区域 |
| 区域 | 4h | 在日线给出的区域内寻找候选入场区和形态 | 候选入场区、失效位 |
| 触发 | 1h、15m | 确认或取消候选：已收盘的突破/跌破、回踩确认、吞没等信号 | 入场时机评分、参考计划 |

规则要点：

- 大周期方向决定只找哪一侧的机会：周线偏多时，小周期的看跌信号只作为回调或减分依据，不单独给出做空建议；反之亦然。
- 周期冲突（例如周线偏多、日线跌破主要结构）时输出“观望”，并列出冲突的周期和证据。
- 入场区、止损、目标优先参考上一级周期的关键位，再用触发周期的ATR微调；不能只用触发周期的ATR倍数。
- 只使用已收盘的K线判断大周期状态；当前未收盘的周线/月线只作暂态展示。
- 每个周期需要足够历史让指标暖机：周线至少100根（EMA50需要），月线不足时只作参考、不参与打分。
- 界面同时显示各周期状态矩阵（方向、关键位、最近信号），并可点击切换到对应周期的K线。

初版实现（现位于 web/js/core/）：方向偏向 = EMA20与EMA50同向且收盘价在EMA50同侧，否则震荡；关键位 = 左右各2根确认的摆动高低点；只有日线反向才判冲突，4h/1h反向视为回调；月线不否决，只加减分和提示；大周期加减分权重 `MTF_W`（1M 3、1w 6、1d 5、4h 4、1h 3，合计±15）；入场区取上一级支撑/阻力起0.5 ATR（当前周期），止损再外推0.5 ATR，目标取上一级反向关键位，不足1 ATR时用2倍风险；状态为已触发/观察中/观望，最新价越过止损或距入场区超过2 ATR时降为观察中。模拟数据由同一条15m路径聚合出各周期，保证价格一致。

原实现思路：在现有 `analyze(bars)` 之上增加 `analyzeMTF(item)`，按周期从大到小依次取K线、调用 `analyze`，把上一级的方向与关键位作为下一级的过滤条件，最终在触发周期上给出评分和参考计划。评分规则需要相应加入“与大周期方向一致/冲突”的加减项，具体权重留待回测确定。数据源需支持周线和月线：eToro代理要核实是否提供1w/1M，Binance支持1w/1M，CSV导入按周期分别提供或由日线聚合（聚合须确认周/月的起止边界）。
